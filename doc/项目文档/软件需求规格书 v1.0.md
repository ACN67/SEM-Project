# 产业智能报告自动生成系统｜软件需求规格书
软工管 G05 · v1.0 · 2026-11-18 · 开发需求基线  
负责人 常珂舒；需求核验分工：王凯乐（来源）、陈易（指标）、潘永健（写作）、叶泽晨（任务与版本）、廖晨皓（用户操作）、常珂舒（模板与导出）。

## 1　用户、范围与流程

研究员为政府智库、产业规划或行业研究任务配置报告，查看结论依据并向他人交付文件。资料管理员为可信团队成员，维护公开数据、年报与政策原文。系统在可信课程演示网络内运行，管理员控制导入入口，研究员从网页生成和编辑。资料上传、生成、质检和导出可由一人依次演示。依据为课程课题 2、2026 年课程评分细则、原计划及本组对五类范围的确认。尚无访谈或实际使用数据作为效果证明。

业务流程：管理员登记原文并检查就绪状态 → 研究员选择报告类型、主题、地区、期间与重点 → 系统冻结资料与模板，显示任务进度 → 研究员查看正文、图表及证据 → 直接导出合格版本，或编辑并更新受影响章节后导出新版本。预建库以外的实时搜索、自动爬取、扫描件通用 OCR 和复杂多租户权限不在交付范围。

## 2　五类报告与验收输入

以下各行均为必交功能，由研究员发起。A、B 在 W5 完成，C、D、E 在 W7 完成，W9 全部复验。时间、地区与企业为本项目选用的验收条件，日后使用者可在资料覆盖范围内更换。数据清单须保留发布单位、日期、原件版本及页码或表格位置。

|需求／案例|输入、结构与业务规则|可检查的结果及缺口处理|
|---|---|---|
|R01 产业分析 A|中国新能源汽车，2022–2024；使用中汽协同口径年度销量和产业政策。含概况、市场规模、产业链、政策、趋势和摘要。|三个年度观测绘制趋势图，至少一项同比与人工核算相同。缺年显示缺口，不插值。|
|R02 企业对标 B|比亚迪、上汽集团 2023–2024 年报；比较研发投入。选至少两个不同企业，按期间、币种、合并范围及指标定义对齐。|输出企业×年份对照表及差异说明；同一企业重复选择被拒绝，研发费用与研发投入不混排。|
|R03 景气 C|中国新能源汽车 2024 年一至四季度销量及 2023 对应期间；可由同源月度销量按季求和。以销量同比作为景气观察指标。|给出四季走势、同比和驱动证据。相邻季度同比增速上升、持平、下降分别写作增速加快、持平、放缓；高增长但减速须能区分。缺同期或基数为零显示不可计算。|
|R04 招商 D|合肥新能源汽车产业链；输入目标地区、目标环节（动力电池配套）、地方产业规划、企业公开产品和布局资料。|输出产业需求、候选企业、匹配依据、限制和接洽建议；至少一个候选同时关联当地需求和企业能力两侧证据。缺任一侧则列为待核实，不得声称已签约或有投资意向。|
|R05 出海研判 E|中国纯电动乘用车进入德国；指定原产地、目的市场、产品及研究截止日。采用目标市场注册统计、贸易或准入措施的正式文本。|输出市场机会、进入条件、风险和行动建议。每项政策标明适用对象、日期及出处；区分纯电乘用车与全部新能源汽车。无适用依据时明确缺口，不宣称符合准入。|

正向案例均应有足够资料形成必需章节。每类至少由一名非生成模块成员抽核一项核心判断及其证据。测试所用真实值、原文定位与预期结论在运行前登记；改输入时另存清单，测试报告记录实际结果。

## 3　共用功能需求

以下均为终期必需。资料管理员执行 R06，研究员使用 R07–R13；系统在用户操作过程中自动完成计算、检查与版本维护。

|编号、功能|前置／输入与处理|输出、异常及验收|
|---|---|---|
|R06 资料导入|管理员上传 PDF、DOCX、XLSX 或 CSV，登记标题、机构、日期和可用原文链接；仅索引解析成功的文件。|相同内容去重，同名异内容形成新版本；超 50 MiB 或不支持格式拒绝。错文件和正常文件分别显示原因与 READY 状态。|
|R07 需求配置|选择五类之一及相应模板，输入产业、地区、起止年度、研究重点。企业列表、招商环节、出海产品与市场按类型要求校验；政策判断带截至日期。|提交后得到报告和任务 ID。缺类型专用字段或起年晚于止年时指出字段且不发起模型调用；同键同请求重复提交仅建一项任务。|
|R08 章节写作|按模板规划必需章节，冻结资料版本。以每章证据包、计算值及前置摘要生成公文风格正文；摘要与结论在依赖就绪后生成。|保留标题顺序和来源，独立章可并行。资料不足标出缺口，无法形成有效必需章时保留草稿并阻止正式导出。|
|R09 计算与图表|按主体、期间、单位、口径选择指标，先计算再写作；同比等于本期减基期后除以基期。|表、图、正文用同一组指标；百分数显示两位小数。基期 0、缺失、口径不符分别给出原因；实际值 0 正常显示。|
|R10 引用与质检|检查必需章、证据白名单、指标一致性和图表资源。用户点击正文引用。|显示版本、原文摘录、页码或单元格；伪引用或结构损坏产生 BLOCK 并阻止导出；仅有 WARN 的完整报告可导出且保留提示。|
|R11 进度与恢复|用户查看任务与章节状态，可取消未完成任务、重试可恢复故障。|返回实际阶段和已完成章数；依赖失败时显示跳过原因。模拟超时或中断后可查错误，重试不重复提交旧结果，迟到结果不覆盖当前尝试。|
|R12 编辑与版本|以指定基版本编辑一章或发起重写。系统复检本章，标记依赖其结论的下游章节。|保存形成新版本；另一人提交过期基版本得到冲突提示。旧版本可复读；新版本有过期章时禁止正式导出，更新并通过检查后恢复。|
|R13 导出与历史|选择已有版本和 DOCX 或 PDF；使用报告内保存的段落顺序、图表与引用。|两种格式与网页逐章对照一致；导出失败时保留在线版本并可重试。未完成的导出不可下载。|

## 4　非功能需求与数据接口

|编号／属性|适用环境、目标与验收方法|
|---|---|
|N01 响应与负载|单机、单 Worker、本地局域网、一个生成任务与两个浏览器会话；预置 100 份报告记录，状态查询重复 20 次，至少 19 次在 2 秒内返回。生成异步运行，不把外部模型耗时计入查询响应。|
|N02 安全与隐私|可信演示部署中，仅管理入口持有导入凭据；无凭据直接上传应拒绝。用公开样本测试，前端网络响应、导出件及仓库样例均不得含模型密钥或服务器绝对路径。|
|N03 可用与兼容|在部署机 Chrome、Edge 各跑一次配置、生成、查看和下载。界面区分运行、成功、告警和失败；DOCX 可由 Word 或 LibreOffice 打开，PDF 中文及图例可读。|
|N04 可追溯与可靠性|保留同一报告的两个版本；替换来源文件并重启服务后，旧版本证据摘录、原件版本和图表仍可核对。运行中断后在恢复流程中形成可查询终态。|

外部数据由管理员提供原件与出处，统计口径保留在指标记录中。PDF 按页，DOCX 按标题与段落，电子表格按工作表与单元格，CSV 按行列定位。后端持有模型密钥，只传本章公开证据和任务上下文；模型输出必须经过结构及引用检查。限流、超时只有限重试，超预算停止调用，错误对用户可见。前端通过版本化 HTTP API 读取业务对象；模型、索引与存储由后端访问。转换器失败只影响本次导出。
